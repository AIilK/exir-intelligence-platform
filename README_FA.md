# نسخه ۲۶ مرکز فرماندهی مالی اکسیر کادوس

## فیلتر زمانی چک‌های پرداختی

- نمایش تا پایان هفته، ۱۰ روز آینده، پایان ماه شمسی، ۳۰ روز آینده یا همه چک‌ها
- مرتب‌سازی از نزدیک‌ترین تاریخ سررسید به دورترین تاریخ
- محاسبه تعداد و مبلغ برای بازه انتخاب‌شده
- دریافت حداکثر ۱۰۰۰ چک باز آینده از SQL Server

## گزارش مدیریتی بازطراحی‌شده

- خلاصه Finance Manager به زبان مدیریتی و یکپارچه نمایش داده می‌شود.
- مبالغ خلاصه به تومان خوانا و درصدها به‌صورت گرد‌شده ارائه می‌شوند.
- کدهای فنی دیتابیس و وضعیت چک از «بهترین اقدام بعدی» حذف شده‌اند.
- هر اقدام برای مدیر با دلیل، اثر مورد انتظار، مسئول و مهلت ارائه می‌شود.

## تیم Agentهای تصمیم‌یار

- Customer Risk Decision Agent: پیش‌بینی ریسک و پیشنهاد سیاست اعتبار
- Cheque Risk Agent: ریسک برگشت و قانون ۹۰ روز
- Cheque Payment Decision Agent: نرخ واقعی پاس‌شدن و ظرفیت پرداخت
- Cash Flow Prediction Agent: پیش‌بینی ۷روزه و پایان ماه
- Collection Decision Agent: مبلغ مورد انتظار وصول و اولویت پیگیری
- Finance Scenario Agent: سناریوی خوش‌بینانه، پایه و بدبینانه
- Representative Performance Agent: کیفیت پرتفوی نمایندگان
- Finance Manager Agent: جمع‌بندی، اولویت‌بندی و برنامه اقدام

هر Agent علاوه بر تحلیل انسانی، `prediction`، `scenarios` و `recommended_actions` دارای مسئول، اولویت، مهلت و اثر مورد انتظار تولید می‌کند.

## قابلیت جدید: Cash Flow روزانه و تحلیل ماه شمسی

در منوی فرانت وارد «Cash Flow روزانه» شوید و فایل xlsx همان روز را بارگذاری کنید. سیستم:

1. تاریخ شمسی را ابتدا از داخل فایل و در صورت نیاز از نام فایل تشخیص می‌دهد.
2. فایل را در آرشیو همان سال و ماه قرار می‌دهد.
3. اگر فایل همان روز قبلاً وجود داشته باشد آن را جایگزین می‌کند.
4. همه فایل‌های همان ماه را از روز اول تا آخرین روز موجود تحلیل می‌کند.
5. میانگین تعهد، فشار چک‌ها، ظرفیت پوشش، روند و پیش‌بینی پایان ماه را نمایش می‌دهد.

نام پیشنهادی فایل: `14050603.xlsx` برای ۳ شهریور ۱۴۰۵.

## اجرای Backend در Windows

```bat
cd backend
python -m venv .venv
.venv\Scripts\activate
python -m pip install -r requirements-v21.txt
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

## اجرای Frontend در پنجره دوم

```bat
cd frontend
npm install
npm run dev -- --host 0.0.0.0
```

سپس روی همان سیستم `http://localhost:3000` و روی سیستم دیگر شبکه `http://IP-SERVER:3000` را باز کنید.

## فعال‌سازی نرخ واقعی پاس‌شدن چک‌های پرداختی

ابتدا Endpoint بالا را اجرا کنید. خروجی `issued_state_distribution` تعداد و مبلغ هر State را نشان می‌دهد. واحد مالی باید مشخص کند کدام State در همین نصب راهکاران به معنی «پاس/تسویه قطعی» است. سپس در `.env` وارد کنید:

```env
TREASURY_ISSUED_PAID_STATES=28
```

در داده‌های بررسی‌شده این شرکت، `State=28` با `DocumentItemType=65` وضعیت پاس/پرداخت قطعی است. `State=15` و وضعیت‌های منفی از مخرج نرخ معتبر حذف می‌شوند. بعد از تغییر `.env`، Backend را یک‌بار Restart کنید.

## تعریف عدد پیش‌بینی

عدد «ظرفیت پرداخت پیش‌بینی‌شده» توان پوشش نقدی بر اساس Snapshotهای Cash Flow است و نرخ قطعی پاس‌شدن چک نیست. نرخ واقعی پاس‌شدن فقط با اتصال وضعیت نهایی چک‌ها از SQL Server محاسبه می‌شود.
# نسخه ۳۰ — پردازش کامل چک‌ها و نمایش خوش‌قولی در پرونده مشتری

تغییرات این نسخه:

- اجرای Agent مالی تمام چک‌های دریافتی باز را بدون سقف ۳۰۰تایی بررسی می‌کند.
- خواندن SQL به‌صورت Batchهای ۱۰۰۰تایی انجام می‌شود.
- فقط ۲۰ چک پرریسک اول و ۱۰ پرتفوی مشتری برای توضیح به LLM ارسال می‌شود.
- نرخ وصول تاریخی، نرخ برگشت، چک‌های عقب‌افتاده و اطمینان سابقه هر مشتری محاسبه می‌شود.
- برای هر مشتری امتیاز خوش‌قولی، درصد اتکای پیشنهادی و سیاست پذیرش چک ساخته می‌شود.
- برای هر چک مبلغ قابل اتکای تعدیل‌شده براساس ریسک محاسبه می‌شود.
- در پرونده مشتری، کارت امتیاز خوش‌قولی، نمودار نرخ وصول و برگشت، درصد اتکا،
  سقف پیشنهادی چک جدید، سیاست اعتباری و دلایل پیشنهاد نمایش داده می‌شود.

برای تست مستقیم تمام چک‌های باز در Swagger:

```text
GET /api/v1/finance/predictions/cheque-return?process_all_open=true
```

اجرای زیر نیز همه چک‌ها را پردازش و نتیجه را به Agent مدیر مالی متصل می‌کند:

```text
POST /api/v1/finance/agents/run-all
```

نکته: امتیاز خوش‌قولی قاعده‌محور و توضیح‌پذیر است. تا زمانی که تاریخ واقعی تسویه
هر چک در SQL تأیید نشود، سیستم ادعای محاسبه «میانگین روز تأخیر واقعی» نمی‌کند.

# نسخه ۳۱ — حذف چک‌های تضمینی از محاسبات

- فقط چک‌های عادی با `NormalORGuarantee = 1` وارد آمار، ریسک، خوش‌قولی،
  پیش‌بینی وصول، پیش‌بینی نقدینگی و پیشنهاد اعتباری می‌شوند.
- چک‌های تضمینی از ریز چک‌های دریافتی و پرداختی، پرونده مشتری، گزارش وضعیت،
  جست‌وجوی بدهکار و تسویه مشتری نیز حذف شده‌اند.
- در خروجی پیش‌بینی ریسک چک، تعداد و مبلغ چک‌های تضمینی حذف‌شده با فیلدهای
  `excluded_guarantee_cheque_count` و `excluded_guarantee_cheque_amount`
  برای کنترل و حسابرسی گزارش می‌شود.
- این تغییر هیچ رکوردی را از SQL Server حذف یا ویرایش نمی‌کند و فقط گزارش‌ها
  و محاسبات را فیلتر می‌کند.
