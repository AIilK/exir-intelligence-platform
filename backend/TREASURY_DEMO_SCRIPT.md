# سناریوی ارائه Treasury Agent اکسیر کادوس

## هدف ارائه

نشان‌دادن اینکه Agent فقط گزارش ثابت نمی‌دهد؛ سؤال فارسی را به ابزار مالی کنترل‌شده
وصل می‌کند، داده واقعی راهکاران را می‌خواند، محاسبه قابل‌ردیابی انجام می‌دهد و
موارد نیازمند تصمیم انسانی را از نتایج قطعی جدا نگه می‌دارد.

## آماده‌سازی

1. Backend و اتصال Read-only راهکاران را اجرا کنید.
2. در `/docs` ابتدا `GET /api/v1/treasury/chat/status` را بررسی کنید.
3. یک فایل صورتحساب بانک واقعی و یک نام مشتری دارای چک آماده داشته باشید.
4. هیچ اطلاعات محرمانه مانند رمز SQL یا کلید OpenAI را روی پرده نمایش ندهید.

## دمو ۱۵ دقیقه‌ای

### ۱. گزارش روزانه مدیر خزانه

در Chat بپرسید:

```text
امروز وضعیت خزانه چطور است و هشدارهای مهم را بگو؟
```

خروجی مورد انتظار: جمع دریافت و پرداخت تأییدشده امروز، خالص اسناد، چک‌های
نزدیک سررسید و هشدارهای معوق. تأکید کنید که خالص اسناد، مانده بانک نیست.

### ۲. ریسک چک تا ۶۰ روز آینده

```text
تا ۶۰ روز آینده چه ریسک چکی داریم؟
```

خروجی مورد انتظار: تعهد چک‌های صادرشده، چک‌های دریافتی، معوق و واخواست‌شده،
شکاف اسمی و طرف حساب‌هایی که بیشترین تمرکز مبلغ را دارند.

### ۳. برنامه پیشنهادی پرداخت

```text
با ۵۰ میلیارد ریال موجودی قابل تخصیص، برنامه پرداخت ۳۰ روز آینده چیست؟
```

خروجی مورد انتظار: ترتیب چک‌ها بر اساس سررسید، مبلغ تجمعی و کسری منابع. Agent
نباید هیچ پرداختی اجرا کند.

### ۴. مغایرت‌گیری بانکی

فایل بانک را در مسیر زیر بارگذاری کنید:

```text
POST /api/v1/treasury/reconciliation/auto-upload
```

سپس `reconciliation_id` را به Chat بدهید:

```text
خلاصه مغایرت‌گیری این شناسه را بگو و مبلغ واریز و برداشت بدون سند را جدا کن: ...
```

خروجی مورد انتظار: سندخورده، برگشت، انتقال داخلی، نیازمند بررسی و بدون سند به
صورت جدا. انتقال داخلی نباید در بدون سند محاسبه شود.

### ۵. چک شخص ثالث و تسویه مشتری

```text
مشتری صابری را بین تحویل‌دهندگان چک پیدا کن.
```

پس از انتخاب نتیجه:

```text
چک‌های این مشتری را بررسی کن؛ بدهی اولیه یک میلیارد ریال بوده است.
```

خروجی مورد انتظار: صاحب چک و بدهکار واقعی جدا، مانده قطعی براساس چک وصول‌شده،
مانده موقت با چک در جریان وصول و حذف چک واخواست‌شده از تسویه.

### ۶. کنترل هوشمند موارد غیرعادی

```text
موارد مالی غیرعادی ۳۰ روز اخیر را با دلیل نشان بده.
```

خروجی مورد انتظار: تکراری احتمالی، مبلغ بزرگ و سند بدون توضیح. توضیح دهید که
این‌ها کاندید بررسی‌اند و اثبات تخلف نیستند.

### ۷. گزارش جامع مدیر

```text
یک گزارش جامع ۳۰ روزه برای مدیر خزانه آماده کن.
```

این سؤال چهار بخش گزارش روزانه، ریسک چک، برنامه پرداخت و کنترل موارد غیرعادی را
یکجا اجرا می‌کند.

## پیام پایانی ارائه

- اتصال به راهکاران فقط خواندنی است.
- Agent اجازه ثبت سند، انتقال وجه یا پرداخت ندارد.
- عدد مالی بدون Tool تولید نمی‌شود.
- موارد مبهم به‌جای حدس‌زدن برای بررسی انسانی باقی می‌مانند.
- مرحله بعد، اتصال فاکتورهای باز فروش و مانده واقعی حساب‌های بانکی به برنامه
  جریان نقد است.
# قابلیت‌های هوشمند جدید

## ۱) سؤال آزاد مالی با SQL امن

در Swagger مسیر `POST /api/v1/treasury/intelligence/ask` را اجرا کنید:

```json
{
  "question": "در ۳۰ روز گذشته پنج پرداخت بزرگ تأییدشده کدام بوده‌اند؟"
}
```

خروجی شامل SQL حسابرسی‌پذیر، فرض‌ها، ردیف‌های نتیجه و محدودیت‌های امنیتی است.
فقط `SELECT` روی فهرست سفید جداول مالی اجرا می‌شود.

همین سؤال را می‌توان از `/api/v1/treasury/chat` نیز پرسید. Agent برای گزارش‌های
ثابت از Tool تأییدشده و برای سؤال جدید از مسیر SQL امن استفاده می‌کند.

## ۲) کشف موارد غیرعادی

از Agent بپرسید:

```text
موارد غیرعادی ۳۰ روز اخیر را با دلیل نشان بده؛ هیچ موردی را تخلف قطعی اعلام نکن.
```

## ۳) سناریوی جریان نقد

در Swagger مسیر `GET /api/v1/treasury/forecast/cashflow` را با نمونه زیر اجرا کنید:

```text
days=30
history_days=90
opening_cash=500000000000
```

خروجی سه سناریوی خوش‌بینانه، محتمل و تنش را نمایش می‌دهد. این نسخه یک مدل
آموزش‌دیده نیست و روش و محدودیت‌های آن صریحاً در پاسخ نوشته می‌شود.

## ۴) تحلیل ریسک و اقدام پیشنهادی

```text
ریسک چک‌ها و فشار نقدینگی ۶۰ روز آینده را تحلیل کن و سه اقدام پیشنهادی بده.
```
