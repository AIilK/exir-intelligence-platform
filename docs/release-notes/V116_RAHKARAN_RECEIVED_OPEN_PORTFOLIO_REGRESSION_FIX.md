# V116 — اصلاح رگرسیون سبد باز چک دریافتی راهکاران

V115 به اشتباه هر State مثبت در تاریخچه ReceivableNoteTransaction را می‌توانست «باز» تلقی کند؛ در نتیجه تعداد سبد از حدود ۸۰۰ به ۲۷۵۷ و مبلغ به حدود ۳۰۰ میلیارد تومان جهش کرد.

در V116:
- کاندید باز فقط ReceivableNote.State IN (1,2) است.
- آخرین ReceivableNoteTransaction تأییدشده فقط نقش override برای حذف وضعیت‌های نهایی دارد.
- محدودیت rnt.State > 0 حذف شد تا عملیات نهایی وصول/مسترد/واخواست در صورت State متفاوت نیز دیده شود.
- وضعیت‌های نهایی حذف‌شونده: مسترد/استرداد، واخواست، نقد شده، وصول شده، واگذار شده به غیر.
- هیچ State تاریخی جدیدی اجازه ندارد سبد باز را بزرگ‌تر از مبنای 1/2 کند.

مبنای کنترل فایل ListData راهکاران:
- وضعیت فعلی باز: 796 چک
- مبلغ: 75,828,510,498 تومان
- وضعیت‌های باز: نزد بانک، نزد صندوق، نزد مأمور وصول، در انتظار واگذاری به مأمور وصول.

این نسخه برای رفع جهش 2757 رکورد طراحی شده است. عدد نهایی دقیق باید بعد از اجرا روی SQL واقعی شرکت با Endpoint کنترلی بررسی شود.
